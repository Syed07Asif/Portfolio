# components/admin/ui/

Generated by shadcn/ui (`npx shadcn add ...`, config in root `components.json`) — **admin panel and interactive overlays only**, per [CLAUDE.md](../../../CLAUDE.md). Currently: `button`, `dialog`, `dropdown-menu`, `tabs`, `form`, `label`, `input`, `select`, `table`, `alert`, `sonner` (toast), `alert-dialog` (confirm).

**This is a separate `button.tsx` from [`components/ui/Button.tsx`](../../ui/Button.tsx)** — that's intentional, not a duplicate to clean up. shadcn's components (`dialog`, `alert-dialog`, `form`, ...) depend on their own Button internally for triggers/actions; keeping it in this folder means it never collides with or gets confused for the public site's hand-built one. The public site (`components/sections`, `components/ui`) must never import from here, and this folder must never import from `components/ui` — the two primitive sets are deliberately kept apart so the public site can't accidentally start looking like a stock shadcn site.

Themed to the same tokens as the rest of the app — see the "shadcn/ui compatibility" block in [`styles/globals.css`](../../../styles/globals.css)'s `@theme inline`. Every CSS variable shadcn's components expect (`--color-card`, `--color-popover`, `--color-secondary`, `--color-muted`, `--color-destructive`, `--color-input`, ...) is an alias onto an existing design token, not a second colour system.

Regenerate or add more with `npx shadcn add <component>`. Don't hand-edit generated files beyond small necessary fixes (e.g. `sonner.tsx` was trimmed to drop a `next-themes` dependency this dark-only site doesn't need) — re-running `add` overwrites local changes.
